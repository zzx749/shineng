# 失能评估辅助系统 · 后端接口文档

> 面向后端同学。本文档说明项目整体情况、数据模型、以及前端对接口的全部要求。
> 前端当前用 mock 运行（localStorage 持久化），本文档中的接口即前后端约定的契约，后端按此实现即可无缝对接。

---

## 一、项目整体总结

### 1. 定位

**老人失能等级评估辅助系统**。核心是「辅助」——系统依据国标 **GB/T 42195-2022《老年人能力评估规范》** 自动计算失能等级，工作人员评估时可纠正，纠正需留痕。

### 2. 角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| `admin` 管理员 | 系统管理员 | 全部功能 + 用户管理 |
| `staff` 评估员 | 一线评估人员 | 老人管理、评估、查看报告，无用户管理 |

### 3. 前端技术栈

Vue 3 + Vite + Element Plus + Vue Router + Pinia + axios。

### 4. 核心业务流程

1. 登录/注册（区分管理员、评估员两种角色）
2. 录入老人基本信息（姓名、年龄、地址、身份证号、电话、儿女电话；**年龄由身份证号自动推算**）
3. 评估：按 4 个一级指标、22 个二级指标打分（每项 0/1/2 分）→ 自动算分 → 得到等级
4. **纠正流程**：系统自动评定等级与工作人员手填判断不一致时，前端高亮警示，可「一键纠正」或人工覆盖（需填纠正说明），最终结果留痕（审计）
5. 报告生成：老人信息 + 各维度得分 + 最终等级 + 评估人 + 日期，可打印/导出 PDF

### 5. 关键设计点

- **接口要少**：全项目约 15 个接口，见下文清单。
- **纠正留痕**：评估记录同时保存「系统计算等级」与「最终等级」两个字段，不一致时标记 `corrected` 并记录 `correctionNote`。
- **前端可切换 mock/真实接口**：前端 `src/api/http.js` 中有 `USE_MOCK` 开关，后端就绪后改为 `false` 即切真实接口，前端代码无需其他改动。

## 二、接口通用约定

### 1. Base URL

前端统一请求前缀：**`/api`**（如 `POST /api/auth/login`）。本文档接口路径省略 `/api` 前缀。

### 2. 认证方式

- 除 `登录`、`注册` 外，所有接口都需登录态。
- 请求头携带：`Authorization: Bearer <token>`
- `token` 由登录/注册接口返回，前端会持久化并在每次请求自动附带。
- token 失效时返回 `401`，前端会自动清空登录态并跳转登录页。

### 3. 统一响应格式

**成功**：HTTP `200`（创建类可用 `201`），返回数据对象（直接返回业务数据，不套外壳）：

```json
{ "list": [], "total": 0 }
```

**失败**：HTTP 4xx/5xx，统一返回错误信息对象：

```json
{ "message": "错误原因描述" }
```

前端统一读取 `message` 字段展示错误。

### 4. 状态码约定

| 状态码 | 含义 |
| --- | --- |
| 200/201 | 成功 |
| 400 | 参数错误 / 业务校验失败（用户名已存在等） |
| 401 | 未登录 / token 失效 |
| 403 | 无权限（如 staff 访问管理员接口） |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

## 三、数据模型

### 1. 用户 User

```json
{
  "id": "u_admin",
  "username": "admin",
  "password": "admin123",
  "name": "系统管理员",
  "role": "admin",
  "createdAt": 1720000000000
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| username | string | 登录名，唯一 |
| password | string | 密码（接口返回给前端时**不应包含此字段**） |
| name | string | 姓名/显示名 |
| role | string | `admin` \| `staff` |
| createdAt | number | 创建时间戳（毫秒） |

### 2. 老人 Elder

```json
{
  "id": "e_demo1",
  "name": "张大爷",
  "gender": "男",
  "age": 78,
  "idCard": "110101194501012233",
  "address": "北京市朝阳区望京街道",
  "phone": "13800001111",
  "childrenPhone": "13900002222",
  "createdAt": 1720000000000,
  "updatedAt": 1720000000000
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| name | string | 姓名（必填） |
| gender | string | `男` \| `女` |
| age | number/null | 年龄，可由身份证号推算 |
| idCard | string | 18 位身份证号 |
| address | string | 家庭住址 |
| phone | string | 联系电话 |
| childrenPhone | string | 儿女/紧急联系人电话 |
| createdAt / updatedAt | number | 时间戳 |

### 3. 评估 Assessment（重点）

```json
{
  "id": "a_xxxx",
  "elderId": "e_demo1",
  "scores": {
    "feeding": 0, "dressing": 1, "bowel": 0, "bladder": 0,
    "toileting": 1, "transfer": 1, "walking": 2, "stairs": 2,
    "bathing": 2, "grooming": 1,
    "cognition": 0, "aggression": 0, "depression": 0,
    "consciousness": 0, "vision": 0, "hearing": 1, "communication": 0,
    "lifeAbility": 1, "workAbility": 1, "timeOrientation": 0,
    "personOrientation": 0, "socialContact": 1
  },
  "dimensionLevels": { "adl": 2, "mental": 0, "sensory": 0, "social": 1 },
  "computedLevel": 2,
  "manualLevel": 2,
  "corrected": false,
  "correctionNote": "",
  "assessor": "评估员小王",
  "assessorId": "u_staff",
  "date": "2026-09-22",
  "createdAt": 1720000000000
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| elderId | string | 关联老人 id |
| scores | object | 22 个二级指标的得分，key 见下表，value 为 `0/1/2` |
| dimensionLevels | object | 四个维度的等级 `{adl, mental, sensory, social}`，value `0-3` |
| computedLevel | number | **系统自动计算**的综合等级 `0-3` |
| manualLevel | number | **工作人员最终确认**的等级 `0-3`（默认等于 computedLevel） |
| corrected | boolean | 是否发生过纠正（manualLevel ≠ computedLevel 时为 true） |
| correctionNote | string | 纠正说明（corrected 为 true 时必填） |
| assessor / assessorId | string | 评估人姓名 / id |
| date | string | 评估日期 `YYYY-MM-DD` |
| createdAt | number | 时间戳 |

> **关于 `scores` 的 22 个 key**（与国标 4 维度对应）：

| 维度 | key（指标） |
| --- | --- |
| 日常生活活动能力 (adl) | `feeding` 进食、`dressing` 穿脱衣、`bowel` 大便控制、`bladder` 小便控制、`toileting` 如厕、`transfer` 床椅转移、`walking` 平地行走、`stairs` 上下楼梯、`bathing` 洗澡、`grooming` 修饰 |
| 精神状态 (mental) | `cognition` 认知功能、`aggression` 攻击行为、`depression` 抑郁症状 |
| 感知觉与沟通 (sensory) | `consciousness` 意识水平、`vision` 视力、`hearing` 听力、`communication` 沟通交流 |
| 社会参与 (social) | `lifeAbility` 生活能力、`workAbility` 工作能力、`timeOrientation` 时间/空间定向、`personOrientation` 人物定向、`socialContact` 社会交往能力 |

## 四、评分规则（GB/T 42195-2022）

> ⚠️ 以下各维度「总分 → 等级」阈值为**占位近似值，需专业老师最终确认后调整**。前端写在 `src/constants/scoring.js`，后端如需复算请以最终确认值为准。

### 等级定义

综合等级（`computedLevel` / `manualLevel`）：

| 值 | 含义 |
| --- | --- |
| 0 | 能力完好 |
| 1 | 轻度失能 |
| 2 | 中度失能 |
| 3 | 重度失能 |

### 综合评级规则

- 全部维度「完好」→ 能力完好
- 出现轻度（无中度/重度）→ 轻度失能
- 出现中度（无重度）→ 中度失能
- 出现重度 → 重度失能

### 维度阈值（占位）

每项 0/1/2 分，维度总分落入区间即对应等级：

| 维度 | 满分 | 完好(0) | 轻度(1) | 中度(2) | 重度(3) |
| --- | --- | --- | --- | --- | --- |
| 日常生活活动能力 adl | 20 | 0 | 1-5 | 6-12 | 13-20 |
| 精神状态 mental | 6 | 0 | 1-2 | 3-4 | 5-6 |
| 感知觉与沟通 sensory | 8 | 0 | 1-2 | 3-5 | 6-8 |
| 社会参与 social | 10 | 0 | 1-3 | 4-6 | 7-10 |

## 五、接口清单

### 认证 Auth

#### 1. 登录

- `POST /auth/login`（无需登录）
- 请求体：

```json
{ "username": "admin", "password": "admin123" }
```

- 成功响应（`200`）：

```json
{
  "token": "t_xxx",
  "user": { "id": "u_admin", "username": "admin", "name": "系统管理员", "role": "admin", "createdAt": 1720000000000 }
}
```

- 失败：`401` `{ "message": "用户名或密码错误" }`

#### 2. 注册

- `POST /auth/register`（无需登录）
- 请求体：

```json
{ "username": "wang", "password": "123456", "name": "王评估员" }
```

- 成功响应（`200`）：同登录，返回 `{ token, user }`（`role` 固定为 `staff`）
- 失败：`400` 用户名已存在 / 参数缺失

#### 3. 当前用户信息（可选，用于会话恢复）

- `GET /auth/me`（需登录）
- 成功响应：`{ "id": "...", "username": "...", "name": "...", "role": "...", "createdAt": ... }`

### 老人管理 Elders

#### 4. 老人列表

- `GET /elders?keyword=张`（需登录）
- query 参数：`keyword`（可选，模糊匹配姓名/身份证/电话）
- 成功响应：

```json
{ "list": [ { /* Elder */ } ], "total": 1 }
```

#### 5. 新增老人

- `POST /elders`（需登录）
- 请求体（`id`、`createdAt`、`updatedAt` 由后端生成）：

```json
{ "name": "张大爷", "gender": "男", "age": 78, "idCard": "110101194501012233", "address": "北京市朝阳区", "phone": "13800001111", "childrenPhone": "13900002222" }
```

- 成功响应（`201`）：完整的 Elder 对象

#### 6. 老人详情

- `GET /elders/:id`（需登录）→ Elder 对象；`404` 不存在

#### 7. 更新老人

- `PUT /elders/:id`（需登录）→ 更新后的 Elder 对象

#### 8. 删除老人

- `DELETE /elders/:id`（需登录）→ `{ "ok": true }`
- **注意**：删除老人时，其关联的评估记录也应一并删除（级联）

### 评估 Assessments

#### 9. 评估列表

- `GET /assessments?elderId=xxx`（需登录）
- query 参数：`elderId`（可选，按老人筛选）
- 成功响应：

```json
{ "list": [ { /* Assessment */ } ], "total": 1 }
```

#### 10. 新增评估

- `POST /assessments`（需登录）
- 请求体：

```json
{
  "elderId": "e_demo1",
  "scores": { "feeding": 0, "dressing": 1, "...": 0 },
  "dimensionLevels": { "adl": 2, "mental": 0, "sensory": 0, "social": 1 },
  "computedLevel": 2,
  "manualLevel": 2,
  "corrected": false,
  "correctionNote": "",
  "date": "2026-09-22"
}
```

- 说明：`scores` 为 22 项打分；`dimensionLevels`/`computedLevel` 为前端自动计算结果；`manualLevel`/`corrected`/`correctionNote` 为工作人员最终判断与留痕；`assessor`/`assessorId` 由后端根据 token 自动填充。
- 成功响应（`201`）：完整的 Assessment 对象

#### 11. 评估详情

- `GET /assessments/:id`（需登录）→ Assessment 对象

### 报告 Reports

#### 12. 获取报告数据

- `GET /reports/:assessmentId`（需登录）
- 成功响应（一次返回报告所需的全部数据）：

```json
{
  "assessment": { /* Assessment 对象 */ },
  "elder": { /* Elder 对象 */ }
}
```

### 用户管理 Users（仅管理员）

> 以下接口需 `role = admin`，否则返回 `403`。

#### 13. 用户列表

- `GET /users`（需 admin）→ `{ "list": [ { /* User 不含 password */ } ], "total": n }`

#### 14. 更新用户

- `PUT /users/:id`（需 admin）
- 请求体（字段均可选，按需更新）：

```json
{ "name": "新名字", "role": "admin", "password": "新密码（可选，留空不改）" }
```

- 成功响应：更新后的 User 对象（不含 password）

#### 15. 删除用户

- `DELETE /users/:id`（需 admin）→ `{ "ok": true }`
- **注意**：不能删除自己

## 六、前后端对接说明

1. **切换真实接口**：后端就绪后，前端只需改 `src/api/http.js`：
   - `USE_MOCK` 改为 `false`
   - 确认 `baseURL`（当前为 `/api`）与后端地址一致（或由代理转发）
2. **计算职责划分**：当前「维度等级 + 综合等级」由**前端计算**（`src/constants/scoring.js`），后端主要做存储与校验。若需后端复算/权威计算，前端可改为只传 `scores`、由后端返回 `dimensionLevels`/`computedLevel`——但需提前对齐，避免两端规则不一致。
3. **时间戳**：`createdAt`/`updatedAt` 为毫秒时间戳；日期 `date` 为 `YYYY-MM-DD` 字符串。
4. **列表分页**：当前列表接口一次性返回全量（`{list, total}`），未做分页。数据量增大后如需分页，请在此文档基础上协商新增 `page`/`pageSize` 参数。
